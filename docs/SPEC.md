# All-in 排排站 規格書

版本：v0.11（2026-11-25）
狀態：草稿，待使用者確認第 13 節的假設。

---

## 1. 範圍

### 1.1 目標

- 3–13 人的合作式網頁遊戲。
- 牌力比較採用德州撲克規則。
- 玩家依自己的手牌估計牌力順位，全隊排對順序才過關。
- 房主開房後產生連結，其他玩家用連結加入。
- 不自建伺服器。網頁是靜態檔案，玩家之間用 P2P 連線。

### 1.2 非目標（第 1 版不做）

- 房主斷線後轉移房主。
- 防止房主作弊（Mental Poker 加密洗牌）。
- TURN relay（無法 P2P 連線的網路不支援）。
- App 內聊天。
- 帳號、戰績保存、排行榜。

## 2. 名詞表

本文件與程式中，每個名詞只有 1 個意思。

| 名詞 | 程式名稱 | 定義 |
|---|---|---|
| 房主 | `host` | 建立房間的玩家。房主的瀏覽器負責全部判定。房主也參與遊戲。 |
| 玩家 | `player` | 房間中的任何參與者，包括房主。 |
| 人數 | `N` | 本場遊戲的玩家數，3 ≤ N ≤ 13。 |
| 場 | `match` | 從房主在大廳按開始，到房主讓全員回到大廳為止。 |
| 局 | `hand` | 發 1 次牌到攤牌的過程。1 場包含多局。 |
| 輪 | `round` | 1 局中的 1 次順位選擇。1 局有 4 輪。 |
| 手牌 | `holeCards` | 每位玩家的私人牌，預設 2 張，可設為 3 張。 |
| 公牌 | `board` | 全員共用的牌，最多 5 張。 |
| 順位 | `rank` | 1..N 的整數。1 代表牌力最小，N 代表牌力最大。 |
| 籌碼 | `persistence` | 玩家在衝突或挑戰中下注的量。畫面不顯示數字。 |
| 衝突 | `conflict` | 2 位以上玩家鎖定同一個順位。 |
| 排序 | `sort` | 衝突後，全員依選的順位與籌碼排出 1..N。 |
| 交換階段 | `swap` | 排序後的限時階段，玩家可移到別人的順位。 |
| 交換請求 | `swapRequest` | 1 位玩家請求移到另 1 位玩家的順位。 |
| 挑戰 | `challenge` | 交換請求被拒絕後，用籌碼決定是否移動。房主可在大廳關閉。 |

## 3. 遊戲規則

### 3.1 1 局的流程

| 步驟 | 發牌 | 動作 |
|---|---|---|
| 1 | 每人 2 張手牌 | 第 1 輪：選順位 → 衝突處理 → 交換階段 |
| 2 | 3 張公牌（flop） | 第 2 輪：選順位 → 衝突處理 → 交換階段 |
| 3 | 第 4 張公牌（turn） | 第 3 輪：選順位 → 衝突處理 → 交換階段 |
| 4 | 第 5 張公牌（river） | 第 4 輪：選順位 → 衝突處理 → 交換階段 |
| 5 | 無 | 攤牌：公開全部手牌，判定本局成敗 |

- 若 `skipRound` 為 1–3，該輪不進行。該輪的公牌併入下一輪一起發。
  - 跳過第 1 輪：開局同時發手牌與 3 張公牌，從第 2 輪開始。
  - 跳過第 2 輪：第 1 輪結束後一次發 4 張公牌，進入第 3 輪。
  - 跳過第 3 輪：第 2 輪結束後一次發 2 張公牌，進入第 4 輪。
- `round` 保持原本的輪號（1–4）。`history` 只記錄有進行的輪。

### 3.1.1 過場時間

- 選順位、籌碼對決、交換順位開始時，先進入過場，長度為 `introSeconds`。
- 過場期間顯示提示，倒數不開始，房主忽略所有計時動作（選順位、鎖定、下注、交換）。
- 過場結束後，完整的階段時間才開始計算。例如選順位仍有完整的 20 秒。
- 每一輪的過場另外加 2 秒（`boardRevealMs`）給大特效。每一輪都先顯示公告（第 2–4 輪含順位變化），最後 2 秒才發牌並播放大特效：第 1 輪是「你的手牌」，第 2–4 輪是公牌。`introSeconds` 為 0 時不加。

### 3.2 選順位

- 每輪限時 20 秒。
- 玩家可以選 1..N 中的任何順位。選擇期間允許重複。
- 全員即時看到每位玩家目前選的順位和鎖定狀態。
- 玩家按「鎖定」後不能修改順位。若還有玩家沒鎖定，玩家可以按「解除鎖定」，重新選擇。
- 最後 1 位玩家鎖定時，選順位立即結束，之後不能解除。
- 第 2–4 輪開始時，系統把上一輪的最終順位設為預設選擇。
- 未鎖定的玩家再次點選自己目前的順位時，系統把該玩家的激動次數（`hype`）加 1。房主每 150 毫秒（`hypeMs`）最多計 1 次。改選其他順位或新的一輪開始時，次數歸零。
- 全員鎖定時，選順位提前結束。

**超時處理：**
1. 若玩家有選擇但沒鎖定，系統鎖定目前選擇。
2. 若玩家沒有任何選擇（只會發生在第 1 輪），系統在其他玩家處理完後，隨機給 1 個空順位。

### 3.3 衝突處理

1. 系統找出所有被 2 人以上選擇的順位。
2. 衝突中的玩家開啟下注視窗，限時 10 秒。
3. 系統依第 6.2 節的演算法排序全員：先依選的順位，同一順位內籌碼較多者排到較大的順位。沒有遞補。
4. 系統只公布結果（誰取得哪個順位），不公布籌碼數量。

**籌碼平手：** 先提交者勝出。
**視窗超時未提交：** 視為提交 0，提交時間視為截止時間。

### 3.4 交換階段

- 預設 60 秒。房主可設定 0–180 秒，0 代表跳過交換階段。
- 排序後順位是 1..N 的完整排列，沒有空順位。
- **交換成功（移動）：** A 移到 B 的順位。A 和 B 之間的玩家（含 B）各往 A 的原順位方向移 1 位遞補。
  - 例：A–E 的順位是 1–5。B 移到 5 後，C、D、E 變成 2、3、4，B 是 5。

**交換請求：**
1. 玩家 A 點選玩家 B，送出交換請求。
2. B 在 10 秒內選擇「接受」或「拒絕」。
3. 若 B 接受，A 立即移到 B 的順位，中間的玩家遞補。
4. 若 B 在 10 秒內沒有回應，系統視為拒絕。
5. 若 B 拒絕，依挑戰設定處理：
   - `challenge` 為 true：A 可在 5 秒內選擇「挑戰」。
   - `challenge` 為 false：請求結束。

**挑戰（只限 `challenge` 為 true）：**
1. A 和 B 同時開啟下注視窗，限時 10 秒。
2. 若 A 的籌碼較多，A 移到 B 的順位，中間的玩家遞補。
3. 若 B 的籌碼較多或相等且先提交，順位不變。

**限制：**
- 1 位玩家同一時間只能參與 1 筆請求或挑戰。
- 同 1 組玩家（不分方向）在同一個交換階段只能有 1 筆請求。
- 全員看得到每筆請求的雙方和結果，看不到籌碼數量。
- 玩家可按「完成」。完成狀態可取消。全員完成時，交換階段提前結束。
- 已按「完成」的玩家仍然可以收到請求。

**鎖定順位（只限 `lockEnd` 不是 `none`）：**
- 鎖定數量 k = ⌈N ÷ 4⌉：3–4 人 1 個，5–8 人 2 個，9–12 人 3 個，13 人 4 個。
- `low` 鎖定順位 1..k；`high` 鎖定順位 N-k+1..N。
- 每個交換階段，持有鎖定順位的玩家不能提出交換請求，也不能被請求或挑戰。
- 鎖定只在本輪交換階段有效。下一輪重新選順位，再依新的順位判斷。
- 鎖定順位在最小或最大一端，所以移動遞補不會經過鎖定順位。

**交換階段計時結束時：**
- 等待回應的請求取消。
- 進行中的挑戰視窗繼續到結束，然後交換階段結束。

### 3.4.1 最終挑戰（只限 `finalGuess` 為 true）

- 最後一輪交換結束後、攤牌前進行，階段名稱為 `GUESS`，限時 30 秒。
- 目標：順位 N（最大）的玩家。其他玩家各投 1 票，猜目標玩家的牌型（高牌到同花順，共 9 種）。
- 票數公開。玩家可以改票。全部在線的投票者都投票後，立即攤牌。
- 計時結束時，未投票的玩家不計票。
- 票數最多的牌型為答案。沒有任何票，或最高票平手，都算猜錯。
- 電腦玩家等所有真人投票者都投票後，投真人最多票的牌型。沒有真人投票者時，投「兩對」。

### 3.5 攤牌與勝負

- 每位玩家以全部手牌（2 或 3 張）+ 5 張公牌，取最佳 5 張計算牌力。
- **成功條件：** 對任 2 位玩家 i、j，若 `rank_i < rank_j`，則 `strength_i ≤ strength_j`。
- 最終挑戰開啟時，牌型也必須猜對才算成功。
- 牌力相同的玩家，順位順序互換都算正確。
- 本局成功則勝場 +1，失敗則敗場 +1。只累計，沒有勝敗目標。
- 每局結束後，房主選擇「下一局」或「全員回到大廳」。
- 回到大廳時保留設定、比分和在線玩家。房主再按開始時，比分歸零。

### 3.6 籌碼

- 籌碼不消耗。每次衝突與挑戰，玩家都可以提交 0–1 中的任何值。
- 滑桿不顯示刻度和數字。系統內部用 0–1 的浮點數表示滑桿位置，提交值等於滑桿位置。
- 滑桿大小以下注用語顯示：0 為「蓋牌」，未滿 1/3 為「跟注」，未滿 2/3 為「加注」，未滿 1 為「再加注」，1（拉到底）為「All-in！」。送出按鈕為「下注」。

## 4. 房間設定

房主在 LOBBY 階段設定。遊戲開始後不能修改。

| 設定 | 型別 | 預設 | 範圍 |
|---|---|---|---|
| `challenge` | bool | true | 交換被拒絕時，是否可以挑戰 |
| `swapSeconds` | int | 60 | 0–180 |
| `introSeconds` | int | 3 | 0–5。每個計時階段開始前的過場時間。0 代表不暫停 |
| `notifyStyle` | `fullscreen` \| `banner` \| `toast` \| `ticker` | `banner` | 提示樣式 |
| `holeCards` | int | 2 | 2 或 3。特殊挑戰：每人手牌張數 |
| `skipRound` | int | 0 | 0–3。特殊挑戰：每局跳過的輪。0 代表不跳過 |
| `lockEnd` | `none` \| `low` \| `high` | `none` | 特殊挑戰：鎖定最小或最大的順位（見 3.4） |
| `finalGuess` | bool | false | 特殊挑戰：攤牌前的最終挑戰（見 3.4.1） |
| `pickSeconds` | int | 20 | 固定 |
| `persistenceSeconds` | int | 10 | 固定 |

---

### 4.1 電腦玩家

- 房主在 LOBBY 按「加入電腦玩家」新增座位，可以按 ✕ 移除。電腦玩家計入人數，總數上限 13 人。
- 電腦玩家的 ID 以 `bot-` 開頭。任何人都不能用這種 ID 加入或接管電腦座位。
- 房主的瀏覽器驅動電腦玩家（`HostSession`）。電腦只使用公開狀態與自己的私人狀態，不看其他手牌。
- 每輪開始時，電腦用蒙地卡羅模擬估計自己的期望順位：隨機發出其他玩家的手牌與未公開的公牌。
- 決策（`src/core/bot.ts`）：
  - 選順位：選最接近估計值、且沒被別人鎖定的順位，然後鎖定。
  - 衝突下注：估計值比爭奪的順位越大，出價越高（想排到較大的順位）。
  - 挑戰下注：出價依「目標順位與估計值的差距」決定。差距越小，出價越高。
  - 交換：被請求時，若遞補後的順位（往請求者原順位移 1 位）更接近估計值就接受。若自己的順位和估計值差 1 以上，向估計順位的持有者提出 1 次交換。不主動挑戰。不和鎖定順位交換。
  - 最終挑戰：跟隨真人的最多票（見 3.4.1）。
- 每個動作前，電腦等待 1.2–3.7 秒，並等過場結束。

## 5. 系統架構

### 5.1 部署

- Vite + TypeScript 建置成靜態檔案。
- 部署到 GitHub Pages、Netlify 或 Cloudflare Pages 中的任 1 個。

### 5.2 連線

- 使用 `trystero` 建立 WebRTC 連線，signaling 走公共 Nostr relay。
- 房號：5 碼 Crockford Base32（排除 I、L、O、U），約 3,300 萬種組合。
- 房號同時作為 Trystero 的 `password`，用來加密 signaling 資料。
- 加入連結格式：

```
https://<網域>/#<房號>
```

- 大廳畫面顯示連結、「複製」按鈕和 QR code。

### 5.3 權威模型

房主的瀏覽器是唯一的判定者：

| 房主負責 | 一般玩家負責 |
|---|---|
| 洗牌、發牌 | 顯示畫面 |
| 計時 | 送出操作 |
| 驗證並套用操作 | 依截止時間戳記顯示倒數 |
| 衝突處理、排序、交換 | — |
| 牌力判定、勝負 | — |

- 玩家操作送到房主。房主驗證後更新狀態，再廣播 `publicState`。
- 房主自己的操作走同一條本機路徑，不經網路，但經過相同的驗證程式。

### 5.4 模組

| 模組 | 職責 | 是否依賴網路 |
|---|---|---|
| `core/cards` | 牌、洗牌 | 否 |
| `core/evaluator` | 7 選 5 牌力計算 | 否 |
| `core/resolve` | 衝突、排序、超時處理 | 否 |
| `core/engine` | 狀態機（純函式：`(state, action, now) → state`） | 否 |
| `net/transport` | Trystero 封裝、訊息收發 | 是 |
| `net/host` | 房主端：計時器、呼叫 engine、廣播 | 是 |
| `net/client` | 玩家端：時鐘校正、送出操作 | 是 |
| `ui/*` | 畫面 | 否 |

`core/*` 不依賴瀏覽器 API，可以直接做單元測試。

## 6. 演算法

### 6.1 洗牌

- 使用 `crypto.getRandomValues` 產生亂數。
- 使用 Fisher-Yates 洗牌，用拒絕取樣消除取模偏差。
- 發牌順序：先發每人 `holeCards` 張手牌，再依序發 5 張公牌。公牌在對應階段才公開。13 人 × 3 張 + 5 張 = 44 張，不會超過 52 張。

### 6.2 衝突與排序

**輸入：** 每位玩家鎖定的順位（可能缺），以及衝突中的籌碼和提交時間。
**輸出：** 1..N 的完整排列。

1. 沒有選擇的玩家，系統隨機給 1 個選擇（1..N），沒有下注。
2. 全員依選的順位由小到大排序。
3. 同一個順位內，籌碼較少者在前；籌碼相等時，較晚提交者在前；再相等時，座位較後者在前。
4. 排序後的位置（1..N）就是順位。沒有遞補，勝者也不一定保留原本選的順位。

**範例：** N = 5。A、B、C 選 3，D 選 5，E 選 1。籌碼 A > C > B。
- 排序：E(1)、B(3)、C(3)、A(3)、D(5)。
- 結果：E=1、B=2、C=3、A=4、D=5。

### 6.3 牌力計算

- 從 7 張牌中列舉 21 種 5 張組合，取最大值。
- 牌力編碼成 1 個整數，可直接比較大小：`類別 × 16^5 + 5 個比較點數`。
- 類別由小到大：高牌、一對、兩對、三條、順子、同花、葫蘆、四條、同花順。
- A-2-3-4-5 是最小的順子，比較點數以 5 為最大。
- 不區分花色大小。

## 7. 狀態機

### 7.1 階段

```
LOBBY
  └─ 房主按開始（N ≥ 3）→ DEAL
DEAL（發 `holeCards` 張手牌；若跳過第 1 輪，同時公開 3 張公牌）→ PICK
PICK（20 秒）
  └─ 全員鎖定或超時 → RESOLVE
RESOLVE
  ├─ 有衝突 → PERSIST（10 秒）→ RESOLVE 完成排序 → SWAP
  └─ 無衝突 → SWAP
SWAP（swapSeconds 秒；0 則跳過）
  └─ 全員完成或超時 → REVEAL
REVEAL
  ├─ 第 1–3 輪 → 翻開下一批公牌 → PICK
  ├─ 第 4 輪，finalGuess 為 true → GUESS
  └─ 第 4 輪，finalGuess 為 false → SHOWDOWN
GUESS（30 秒）
  └─ 全員投票或超時 → SHOWDOWN
SHOWDOWN（顯示結果，累計勝敗）
  ├─ 房主按下一局 → DEAL
  └─ 房主按全員回到大廳 → LOBBY（保留設定、比分、在線玩家）
任何階段：房主斷線 → CLOSED
```

### 7.2 狀態資料（房主持有）

```ts
interface HostState {
  phase: Phase;
  settings: RoomSettings;
  players: PlayerSeat[];        // 依加入順序
  deck: Card[];                 // 只在房主端
  holeCards: Record<PlayerId, [Card, Card]>; // 只在房主端
  board: Card[];                // 已公開的公牌
  round: 1 | 2 | 3 | 4;
  picks: Record<PlayerId, Pick>;
  ranks: Record<PlayerId, number>;           // 上一次排序或交換後的順位
  history: Record<PlayerId, number[]>;       // 本局每輪交換結束後的順位，新局清空
  conflict?: ConflictState;
  swap?: SwapState;
  score: { wins: number; losses: number };
  deadline?: number;            // 房主時鐘的毫秒時間戳記
}
```

`deck`、`holeCards` 不放進 `publicState`。

## 8. 訊息協定

所有訊息都包含 `v`（協定版本，目前為 9；v9 新增 `lockEnd`、`finalGuess`、`guessVote`；v2 新增 `history`，v3 新增 `unlock`，v4 新增過場與提示設定、`startsAt`，v6 移除 `MATCH_END`、新增 `lobby`，v7 移除預算、`persistenceMode` 改為 `challenge`，v8 移除房間設定 `sound`、`vibrate`）。版本不同的玩家無法加入。

### 8.1 玩家 → 房主

| 類型 | 欄位 | 允許階段 |
|---|---|---|
| `join` | `playerId`, `name` | LOBBY；或任何階段的重連 |
| `pick` | `rank` | PICK，且未鎖定 |
| `lock` | — | PICK |
| `unlock` | — | PICK，且已鎖定 |
| `persist` | `value`（0–1） | PERSIST 或挑戰視窗，且為參與者 |
| `swapRequest` | `targetId` | SWAP |
| `swapRespond` | `requestId`, `accept` | SWAP，且為被請求者 |
| `swapChallenge` | `requestId` | SWAP，且為請求者，拒絕後 5 秒內 |
| `swapDone` | `done` | SWAP |
| `guessVote` | `category`（0–8） | GUESS，且不是目標玩家 |
| `next` | — | SHOWDOWN，只有房主 |
| `lobby` | — | SHOWDOWN，只有房主 |
| `addBot` | — | LOBBY，只有房主 |
| `removeBot` | `targetId` | LOBBY，只有房主 |
| `ping` | `t0` | 任何階段 |

### 8.2 房主 → 玩家

房主對每位玩家個別送出訊息，所以私人資料可以和公開資料放在同 1 則訊息中。

| 類型 | 對象 | 欄位 |
|---|---|---|
| `state` | 單一玩家 | `pub`：公開狀態（階段、公牌、玩家、選擇、順位、衝突參與者與已提交者、交換請求、比分、`deadline`、攤牌結果）。`priv`：該玩家的手牌。`hostNow`：房主時鐘。 |
| `rejected` | 單一玩家 | 原因：`full`、`started`、`version` |
| `pong` | 單一玩家 | `t0`, `hostNow` |

- 下注視窗由玩家端從 `pub` 推導：自己是衝突或挑戰參與者，且尚未提交。
- 房主離線時不送訊息。玩家端偵測到房主的連線中斷，就顯示遊戲結束。

### 8.3 驗證規則

- 房主以 Trystero 的 `peerId` 對應 `playerId`。訊息中的身分欄位一律忽略。
- 階段不符、數值超出範圍或重複操作的訊息，房主直接丟棄，不回覆錯誤。
- `persist.value` 超出 0–1 時，房主截斷到 0–1。

## 9. 計時與時鐘校正

- 所有截止時間都用房主時鐘的毫秒時間戳記。
- 玩家加入時送 5 次 `ping`。玩家取往返時間最短的 1 次，計算時鐘差：
  `offset = hostNow − (t0 + rtt / 2)`。
- 玩家顯示倒數：`deadline − (Date.now() + offset)`。
- 只有房主的計時器會觸發階段轉換。玩家端倒數只用來顯示。
- 房主收到截止時間後 300 毫秒內的操作仍然接受，用來吸收網路延遲。

## 10. 斷線與重連

| 情況 | 處理 |
|---|---|
| 玩家在 LOBBY 斷線 | 移除座位。 |
| 玩家在遊戲中斷線 | 保留座位。所有計時操作依超時規則處理。畫面標示「離線」。 |
| 玩家重連 | 玩家以 localStorage 中的 `playerId` 送 `join`。房主恢復對應，重送 `privateHand`。 |
| 房主斷線 | 玩家端偵測到房主離開後，顯示「房主已離線，遊戲結束」。 |
| 房主重新整理頁面 | 等同房主斷線。第 1 版不保存房主狀態。 |

## 11. 安全與隱私

| 項目 | 做法 |
|---|---|
| 手牌保密 | `privateHand` 只送給本人。`publicState` 不包含任何手牌。 |
| 房主介面 | 房主畫面只顯示房主自己的手牌。 |
| 房主作弊 | 第 1 版不防止。房主可用 DevTools 看到全部手牌，說明頁需告知玩家。 |
| 洗牌隨機性 | 使用 `crypto.getRandomValues`。 |
| 房號猜測 | 5 碼約 3,300 萬種組合，並作為 signaling 加密密碼。 |
| 輸入驗證 | 暱稱限 1–12 字，去除控制字元；顯示時一律當純文字，不插入 HTML。 |

## 12. 畫面

| 畫面 | 主要內容 |
|---|---|
| 首頁 | 輸入暱稱、「建立房間」按鈕。若 URL 有房號，改為「加入房間」。 |
| 大廳 | 連結、複製按鈕、QR code、玩家清單、房主設定、「開始」按鈕（只有房主）。 |
| 牌桌 | 自己的手牌、公牌、順位列（1..N，每格顯示選擇該順位的玩家）、倒數、鎖定按鈕。 |
| 下注視窗 | 無刻度滑桿（兩端為「蓋牌」與「All-in」）、即時下注用語、倒數、「下注」按鈕。 |
| 交換階段 | 順位列、點選玩家送出請求、收到請求的彈出卡、請求紀錄、「完成」按鈕。 |
| 攤牌 | 全部手牌、牌型、正確順序與玩家順位的對照、本局成敗、比分。 |

**順位顯示：**
- 順位列一律由小到大排列：1（最小）在最上方，N（最大）在最下方。攤牌表格也相同。
- 牌桌和攤牌畫面顯示「各輪順位」表格：每位玩家在本局每輪交換結束後的順位，並以箭頭標示和上一輪相比的升降。
- 表格依最近一輪的順位由小到大排列。人數多時，玩家可以參考其他人的順位變化推測牌力。
- 選順位時，每位玩家的標籤旁顯示上一輪順位（例如「前 3」）。
- 順位 1 和 N 一律標示「最小」和「最大」，包括攤牌表格。

**衝突與交換的資訊：**
- 下注視窗以大字顯示「爭奪的順位」，並標示 1 最小、N 最大。
- 衝突視窗列出搶同一個順位的所有玩家，以及每人前幾輪的順位。
- 交換請求卡片與挑戰視窗並排顯示雙方：目前順位、前幾輪順位。被爭奪的順位以醒目顏色標示。

**進度與特效：**
- 標題列顯示本局進度：翻牌前 → 翻牌 → 轉牌 → 河牌 → 攤牌，以及目前步驟（選順位、籌碼對決、交換順位）。
- 狀態改變時，畫面上方依序跳出公告：開局、發公牌、順位衝突、衝突結果、交換請求、挑戰、交換結果、攤牌。
- 公告最多排隊 2 則，較舊的直接捨棄，避免顯示過時的消息。最新 1 則同時留在標題列下方。
- 階段開始的公告會插隊立即顯示，並持續到過場結束，附過場進度條。
- 提示樣式由房主選擇，全體玩家套用：全螢幕過場（只用於階段開始，其他消息改用橫幅）、上方橫幅、底部提示條、只顯示文字列。
- 大廳有「在我的裝置預覽提示」按鈕，只在本機播放範例，不寫入最新事件列。
- 公告只用公開狀態產生，不會洩漏手牌或籌碼數量。
- 新發的手牌和公牌有翻牌動畫。順位改變時，玩家標籤從舊位置滑到新位置。剛鎖定的玩家標籤彈跳 1 下。
- 選順位時，玩家的激動次數增加，全員畫面上該玩家的標籤變紅並抖動，上方飄出 ❗／🔥。2 秒內點越多次，特效越強：1–3 次為第 1 級，4–7 次為第 2 級，8 次以上為第 3 級（加上「激動！」字樣）。
- 選順位時，若玩家選的順位比上一輪大，標籤持續發金光並標示「↑+差距」；改成較大順位的瞬間放大閃光。
- 交換階段的標籤顯示順位歷程（例如 3→4）。順位互換時，雙方標籤閃金光並出現 ⇄ 標記。
- 翻牌、轉牌與河牌時，畫面中央暗下，新公牌放大翻開並掃過光澤，搭配「翻牌！」「轉牌！」「河牌！」標題，約 1.9 秒後收進牌桌。順序為：先顯示公告與順位變化，新公牌保持牌背；過場最後 2 秒才播放大特效並翻開公牌，之後倒數開始。
- 過場期間顯示「順位變化」面板（有跳出視窗的提示樣式只放在視窗內；「只顯示文字列」樣式放在牌桌上）。名字過長以「…」截斷：進入交換前為「選擇 → 結果」；新一輪開始時為前 2 輪結束時的順位對照，第 2 輪只列確定順位。面板先依原本順位排列並顯示舊順位，約 1 秒後所有列同時滑到新順位，舊數字縮小劃掉、新數字彈出，再顯示 ↑／↓；沒變動的標示「不變」。「最小／最大」放在數字前面。
- 下注視窗與挑戰視窗內顯示公牌與自己的手牌。
- 攤牌從順位 1 開始逐列翻開手牌和對錯。全部翻完後，才顯示成功或失敗、比分和「下一局」。
- 音效、背景音樂與震動由每位玩家自己開關，不屬於房間設定。畫面左下角有「音效」「音樂」「震動」3 個按鈕，選擇存在本機，預設都關閉。震動只在支援的裝置有效。
- 背景音樂由 Web Audio 即時合成（4 個和弦循環的 lo-fi，84 BPM），不載入音檔。瀏覽器要求先點過畫面才會播放。
- 系統設定「減少動態效果」時，關閉所有動畫，公告文字照常顯示。

**版面需求：**
- 以手機直向為主，寬度 360px 可完整操作。
- 順位列在 N = 13 時可橫向捲動，或改為 2 排。
- 不使用瀏覽器原生的 `alert`、`confirm`。

## 14. 時間估計

每局 = 4 ×（20 秒選順位 + 最多 10 秒下注 + 60 秒交換）+ 攤牌 ≈ 6–7 分鐘。
1 場的局數由房主決定，沒有上限。
