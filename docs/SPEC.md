# Rank Poker 規格書

版本：v0.5（2026-11-24）
狀態：草稿，待使用者確認第 13 節的假設。

---

## 1. 範圍

### 1.1 目標

- 3–13 人的合作式網頁遊戲。
- 牌力比較採用德州撲克規則。
- 玩家依自己的手牌估計牌力名次，全隊排對順序才過關。
- 房主開房後產生連結，其他玩家用連結加入。
- 不自建伺服器。網頁是靜態檔案，玩家之間用 P2P 連線。

### 1.2 非目標（第 1 版不做）

- 房主斷線後轉移房主。
- 防止房主作弊（Mental Poker 加密洗牌）。
- TURN relay（無法 P2P 連線的網路不支援）。
- App 內聊天。
- 帳號、戰績保存、排行榜。

## 2. 名詞表

本文件與程式中，每個名詞只有 1 個意思。

| 名詞 | 程式名稱 | 定義 |
|---|---|---|
| 房主 | `host` | 建立房間的玩家。房主的瀏覽器負責全部判定。房主也參與遊戲。 |
| 玩家 | `player` | 房間中的任何參與者，包括房主。 |
| 人數 | `N` | 本場遊戲的玩家數，3 ≤ N ≤ 13。 |
| 場 | `match` | 從開始到 3 勝或 3 敗為止。 |
| 局 | `hand` | 發 1 次牌到攤牌的過程。1 場包含多局。 |
| 輪 | `round` | 1 局中的 1 次名次選擇。1 局有 4 輪。 |
| 手牌 | `holeCards` | 每位玩家的 2 張私人牌。 |
| 公牌 | `board` | 全員共用的牌，最多 5 張。 |
| 名次 | `rank` | 1..N 的整數。1 代表牌力最小，N 代表牌力最大。 |
| 執著度 | `persistence` | 玩家在衝突或挑戰中投入的強度。畫面不顯示數字。 |
| 執著度模式 | `persistenceMode` | `budget`（預算制）或 `free`（無代價）。 |
| 預算 | `budget` | 預算制中，每位玩家每局可用的執著度總量。 |
| 衝突 | `conflict` | 2 位以上玩家鎖定同一個名次。 |
| 遞補 | `fill` | 衝突落敗者移到最近的空名次。 |
| 交換階段 | `swap` | 遞補後的限時階段，玩家可互換名次。 |
| 交換請求 | `swapRequest` | 1 位玩家向另 1 位玩家提出互換名次。 |
| 挑戰 | `challenge` | 交換請求被拒絕後，用執著度決定是否互換（只限預算制）。 |

## 3. 遊戲規則

### 3.1 1 局的流程

| 步驟 | 發牌 | 動作 |
|---|---|---|
| 1 | 每人 2 張手牌 | 第 1 輪：選名次 → 衝突處理 → 交換階段 |
| 2 | 3 張公牌（flop） | 第 2 輪：選名次 → 衝突處理 → 交換階段 |
| 3 | 第 4 張公牌（turn） | 第 3 輪：選名次 → 衝突處理 → 交換階段 |
| 4 | 第 5 張公牌（river） | 第 4 輪：選名次 → 衝突處理 → 交換階段 |
| 5 | 無 | 攤牌：公開全部手牌，判定本局成敗 |

### 3.1.1 過場時間

- 選名次、執著度對決、交換名次開始時，先進入過場，長度為 `introSeconds`。
- 過場期間顯示提示，倒數不開始，房主忽略所有計時動作（選名次、鎖定、執著度、交換）。
- 過場結束後，完整的階段時間才開始計算。例如選名次仍有完整的 20 秒。

### 3.2 選名次

- 每輪限時 20 秒。
- 玩家可以選 1..N 中的任何名次。選擇期間允許重複。
- 全員即時看到每位玩家目前選的名次和鎖定狀態。
- 玩家按「鎖定」後不能修改名次。若還有玩家沒鎖定，玩家可以按「解除鎖定」，重新選擇。
- 最後 1 位玩家鎖定時，選名次立即結束，之後不能解除。
- 第 2–4 輪開始時，系統把上一輪的最終名次設為預設選擇。
- 全員鎖定時，選名次提前結束。

**超時處理：**
1. 若玩家有選擇但沒鎖定，系統鎖定目前選擇。
2. 若玩家沒有任何選擇（只會發生在第 1 輪），系統在其他玩家處理完後，隨機給 1 個空名次。

### 3.3 衝突處理

1. 系統找出所有被 2 人以上選擇的名次。
2. 衝突中的玩家開啟執著度視窗，限時 10 秒。
3. 每個衝突名次的最高執著度者取得該名次。
4. 其他落敗者依第 6.2 節的演算法遞補。
5. 系統只公布結果（誰取得哪個名次），不公布執著度強度。

**執著度平手：** 先提交者勝出。
**視窗超時未提交：** 視為提交 0，提交時間視為截止時間。

### 3.4 交換階段

- 預設 60 秒。房主可設定 0–180 秒，0 代表跳過交換階段。
- 遞補後名次是 1..N 的完整排列，沒有空名次。所以交換只能是兩人互換。

**交換請求：**
1. 玩家 A 點選玩家 B，送出交換請求。
2. B 在 10 秒內選擇「接受」或「拒絕」。
3. 若 B 接受，A 和 B 立即互換名次。
4. 若 B 在 10 秒內沒有回應，系統視為拒絕。
5. 若 B 拒絕，依執著度模式處理：
   - `budget`：A 可在 5 秒內選擇「挑戰」。
   - `free`：請求結束。

**挑戰（只限 `budget`）：**
1. A 和 B 同時開啟執著度視窗，限時 10 秒。
2. 若 A 的執著度較高，A 和 B 互換名次。
3. 若 B 的執著度較高或相等且先提交，名次不變。
4. 雙方都扣除自己提交的執著度。

**限制：**
- 1 位玩家同一時間只能參與 1 筆請求或挑戰。
- 同 1 組玩家（不分方向）在同一個交換階段只能有 1 筆請求。
- 全員看得到每筆請求的雙方和結果，看不到執著度強度。
- 玩家可按「完成」。完成狀態可取消。全員完成時，交換階段提前結束。
- 已按「完成」的玩家仍然可以收到請求。

**交換階段計時結束時：**
- 等待回應的請求取消。
- 進行中的挑戰視窗繼續到結束，然後交換階段結束。

### 3.5 攤牌與勝負

- 每位玩家以 2 張手牌 + 5 張公牌，取最佳 5 張計算牌力。
- **成功條件：** 對任 2 位玩家 i、j，若 `rank_i < rank_j`，則 `strength_i ≤ strength_j`。
- 牌力相同的玩家，名次順序互換都算正確。
- 本局成功則勝場 +1，失敗則敗場 +1。
- 先達 3 勝或 3 敗時，本場結束。

### 3.6 執著度模式

| 項目 | `budget` | `free` |
|---|---|---|
| 每局預算 | 100 單位，下一局重置 | 無 |
| 滑桿範圍 | 0 到剩餘預算 | 0 到 1 |
| 扣除方式 | 衝突與挑戰的全員都扣除自己提交的值 | 不扣除 |
| 畫面顯示 | 只顯示剩餘量條，不顯示數字 | 只顯示滑桿 |
| 挑戰 | 可用 | 不可用 |

- 滑桿不顯示刻度和數字。
- 系統內部用 0–1 的浮點數表示滑桿位置。`budget` 模式提交值 = 位置 × 剩餘預算。
- 其他玩家的剩餘預算不公開。

## 5. 系統架構

### 5.1 部署

- Vite + TypeScript 建置成靜態檔案。
- 部署到 GitHub Pages、Netlify 或 Cloudflare Pages 中的任 1 個。

### 5.2 連線

- 使用 `trystero` 建立 WebRTC 連線，signaling 走公共 Nostr relay。
- 房號：5 碼 Crockford Base32（排除 I、L、O、U），約 3,300 萬種組合。
- 房號同時作為 Trystero 的 `password`，用來加密 signaling 資料。
- 加入連結格式：

```
https://<網域>/#<房號>
```

- 大廳畫面顯示連結、「複製」按鈕和 QR code。

### 5.3 權威模型

房主的瀏覽器是唯一的判定者：

| 房主負責 | 一般玩家負責 |
|---|---|
| 洗牌、發牌 | 顯示畫面 |
| 計時 | 送出操作 |
| 驗證並套用操作 | 依截止時間戳記顯示倒數 |
| 衝突處理、遞補、交換 | — |
| 牌力判定、勝負 | — |

- 玩家操作送到房主。房主驗證後更新狀態，再廣播 `publicState`。
- 房主自己的操作走同一條本機路徑，不經網路，但經過相同的驗證程式。

### 5.4 模組

| 模組 | 職責 | 是否依賴網路 |
|---|---|---|
| `core/cards` | 牌、洗牌 | 否 |
| `core/evaluator` | 7 選 5 牌力計算 | 否 |
| `core/resolve` | 衝突、遞補、超時處理 | 否 |
| `core/engine` | 狀態機（純函式：`(state, action, now) → state`） | 否 |
| `net/transport` | Trystero 封裝、訊息收發 | 是 |
| `net/host` | 房主端：計時器、呼叫 engine、廣播 | 是 |
| `net/client` | 玩家端：時鐘校正、送出操作 | 是 |
| `ui/*` | 畫面 | 否 |

`core/*` 不依賴瀏覽器 API，可以直接做單元測試。

## 6. 演算法

### 6.1 洗牌

- 使用 `crypto.getRandomValues` 產生亂數。
- 使用 Fisher-Yates 洗牌，用拒絕取樣消除取模偏差。
- 發牌順序：先發每人 2 張手牌，再依序發 5 張公牌。公牌在對應階段才公開。

### 6.2 衝突與遞補

**輸入：** 每位玩家鎖定的名次（可能缺），以及衝突中的執著度和提交時間。
**輸出：** 1..N 的完整排列。

1. 只有 1 人選擇的名次，由該玩家取得。
2. 每個衝突名次，由執著度最高者取得；執著度相等時，先提交者取得。
3. 把所有落敗者放進同一個清單。依執著度由高到低排序；相等時，先提交者在前。
4. 依清單順序，每位落敗者取得離原名次最近的空名次。
5. 若 2 個空名次距離相等，取較小的名次。
6. 最後，沒有選擇的玩家依隨機順序，各取 1 個隨機空名次。

**範例：** N = 5。A、B、C 選 3，D 選 5，E 選 1。執著度 A > C > B。
- A 取得 3，D 取得 5，E 取得 1。
- 空名次：2、4。
- C 距離 2 和 4 都是 1，取較小的 2。
- B 只剩 4。
- 結果：E=1、C=2、A=3、B=4、D=5。

### 6.3 牌力計算

- 從 7 張牌中列舉 21 種 5 張組合，取最大值。
- 牌力編碼成 1 個整數，可直接比較大小：`類別 × 16^5 + 5 個比較點數`。
- 類別由小到大：高牌、一對、兩對、三條、順子、同花、葫蘆、四條、同花順。
- A-2-3-4-5 是最小的順子，比較點數以 5 為最大。
- 不區分花色大小。

## 7. 狀態機

### 7.1 階段

```
LOBBY
  └─ 房主按開始（N ≥ 3）→ DEAL
DEAL（發 2 張手牌）→ PICK
PICK（20 秒）
  └─ 全員鎖定或超時 → RESOLVE
RESOLVE
  ├─ 有衝突 → PERSIST（10 秒）→ RESOLVE 完成遞補 → SWAP
  └─ 無衝突 → SWAP
SWAP（swapSeconds 秒；0 則跳過）
  └─ 全員完成或超時 → REVEAL
REVEAL
  ├─ 第 1–3 輪 → 翻開下一批公牌 → PICK
  └─ 第 4 輪 → SHOWDOWN
SHOWDOWN（顯示結果，房主按下一局）
  ├─ 未達 3 勝或 3 敗 → DEAL
  └─ 達到 → MATCH_END
MATCH_END
  └─ 房主按再玩一場 → LOBBY（保留玩家）
任何階段：房主斷線 → CLOSED
```

### 7.2 狀態資料（房主持有）

```ts
interface HostState {
  phase: Phase;
  settings: RoomSettings;
  players: PlayerSeat[];        // 依加入順序
  deck: Card[];                 // 只在房主端
  holeCards: Record<PlayerId, [Card, Card]>; // 只在房主端
  board: Card[];                // 已公開的公牌
  round: 1 | 2 | 3 | 4;
  picks: Record<PlayerId, Pick>;
  ranks: Record<PlayerId, number>;           // 上一次遞補或交換後的名次
  history: Record<PlayerId, number[]>;       // 本局每輪交換結束後的名次，新局清空
  conflict?: ConflictState;
  swap?: SwapState;
  budgets: Record<PlayerId, number>;         // 只在房主端
  score: { wins: number; losses: number };
  deadline?: number;            // 房主時鐘的毫秒時間戳記
}
```

`deck`、`holeCards`、`budgets` 不放進 `publicState`。

## 8. 訊息協定

所有訊息都包含 `v`（協定版本，目前為 4；v2 新增 `history`，v3 新增 `unlock`，v4 新增過場與提示設定、`startsAt`）。版本不同的玩家無法加入。

### 8.1 玩家 → 房主

| 類型 | 欄位 | 允許階段 |
|---|---|---|
| `join` | `playerId`, `name` | LOBBY；或任何階段的重連 |
| `pick` | `rank` | PICK，且未鎖定 |
| `lock` | — | PICK |
| `unlock` | — | PICK，且已鎖定 |
| `persist` | `value`（0–1） | PERSIST 或挑戰視窗，且為參與者 |
| `swapRequest` | `targetId` | SWAP |
| `swapRespond` | `requestId`, `accept` | SWAP，且為被請求者 |
| `swapChallenge` | `requestId` | SWAP，且為請求者，拒絕後 5 秒內 |
| `swapDone` | `done` | SWAP |
| `ping` | `t0` | 任何階段 |

### 8.2 房主 → 玩家

房主對每位玩家個別送出訊息，所以私人資料可以和公開資料放在同 1 則訊息中。

| 類型 | 對象 | 欄位 |
|---|---|---|
| `state` | 單一玩家 | `pub`：公開狀態（階段、公牌、玩家、選擇、名次、衝突參與者與已提交者、交換請求、比分、`deadline`、攤牌結果）。`priv`：該玩家的手牌與剩餘預算比例。`hostNow`：房主時鐘。 |
| `rejected` | 單一玩家 | 原因：`full`、`started`、`version` |
| `pong` | 單一玩家 | `t0`, `hostNow` |

- 執著度視窗由玩家端從 `pub` 推導：自己是衝突或挑戰參與者，且尚未提交。
- 房主離線時不送訊息。玩家端偵測到房主的連線中斷，就顯示遊戲結束。

### 8.3 驗證規則

- 房主以 Trystero 的 `peerId` 對應 `playerId`。訊息中的身分欄位一律忽略。
- 階段不符、數值超出範圍或重複操作的訊息，房主直接丟棄，不回覆錯誤。
- `persist.value` 超出 0–1 時，房主截斷到 0–1。

## 9. 計時與時鐘校正

- 所有截止時間都用房主時鐘的毫秒時間戳記。
- 玩家加入時送 5 次 `ping`。玩家取往返時間最短的 1 次，計算時鐘差：
  `offset = hostNow − (t0 + rtt / 2)`。
- 玩家顯示倒數：`deadline − (Date.now() + offset)`。
- 只有房主的計時器會觸發階段轉換。玩家端倒數只用來顯示。
- 房主收到截止時間後 300 毫秒內的操作仍然接受，用來吸收網路延遲。

## 10. 斷線與重連

| 情況 | 處理 |
|---|---|
| 玩家在 LOBBY 斷線 | 移除座位。 |
| 玩家在遊戲中斷線 | 保留座位。所有計時操作依超時規則處理。畫面標示「離線」。 |
| 玩家重連 | 玩家以 localStorage 中的 `playerId` 送 `join`。房主恢復對應，重送 `privateHand` 和 `privateBudget`。 |
| 房主斷線 | 玩家端偵測到房主離開後，顯示「房主已離線，遊戲結束」。 |
| 房主重新整理頁面 | 等同房主斷線。第 1 版不保存房主狀態。 |

## 11. 安全與隱私

| 項目 | 做法 |
|---|---|
| 手牌保密 | `privateHand` 只送給本人。`publicState` 不包含任何手牌。 |
| 房主介面 | 房主畫面只顯示房主自己的手牌。 |
| 房主作弊 | 第 1 版不防止。房主可用 DevTools 看到全部手牌，說明頁需告知玩家。 |
| 洗牌隨機性 | 使用 `crypto.getRandomValues`。 |
| 房號猜測 | 5 碼約 3,300 萬種組合，並作為 signaling 加密密碼。 |
| 輸入驗證 | 暱稱限 1–12 字，去除控制字元；顯示時一律當純文字，不插入 HTML。 |

| 大廳 | 連結、複製按鈕、QR code、玩家清單、房主設定、「開始」按鈕（只有房主）。 |
| 牌桌 | 自己的手牌、公牌、名次列（1..N，每格顯示選擇該名次的玩家）、倒數、鎖定按鈕。 |
| 執著度視窗 | 無刻度滑桿、剩餘量條（預算制）、倒數、提交按鈕。 |
| 交換階段 | 名次列、點選玩家送出請求、收到請求的彈出卡、請求紀錄、「完成」按鈕。 |
| 攤牌 | 全部手牌、牌型、正確順序與玩家名次的對照、本局成敗、比分。 |
| 結束 | 最終比分、「再玩一場」（只有房主）。 |

**名次顯示：**
- 名次列一律由小到大排列：1（最小）在最上方，N（最大）在最下方。攤牌表格也相同。
- 牌桌和攤牌畫面顯示「各輪名次」表格：每位玩家在本局每輪交換結束後的名次，並以箭頭標示和上一輪相比的升降。
- 表格依最近一輪的名次由小到大排列。人數多時，玩家可以參考其他人的名次變化推測牌力。
- 選名次時，每位玩家的標籤旁顯示上一輪名次（例如「前 3」）。
- 名次 1 和 N 一律標示「最小」和「最大」，包括攤牌表格。

**衝突與交換的資訊：**
- 執著度視窗以大字顯示「爭奪的名次」，並標示 1 最小、N 最大。
- 衝突視窗列出搶同一個名次的所有玩家，以及每人前幾輪的名次。
- 交換請求卡片與挑戰視窗並排顯示雙方：目前名次、前幾輪名次。被爭奪的名次以醒目顏色標示。

**進度與特效：**
- 標題列顯示本局進度：翻牌前 → 翻牌 → 轉牌 → 河牌 → 攤牌，以及目前步驟（選名次、執著度對決、交換名次）。
- 狀態改變時，畫面上方依序跳出公告：開局、發公牌、名次衝突、衝突結果、交換請求、挑戰、交換結果、攤牌。
- 公告最多排隊 2 則，較舊的直接捨棄，避免顯示過時的消息。最新 1 則同時留在標題列下方。
- 階段開始的公告會插隊立即顯示，並持續到過場結束，附過場進度條。
- 提示樣式由房主選擇，全體玩家套用：全螢幕過場（只用於階段開始，其他消息改用橫幅）、上方橫幅、底部提示條、只顯示文字列。
- 大廳有「在我的裝置預覽提示」按鈕，只在本機播放範例，不寫入最新事件列。
- 公告只用公開狀態產生，不會洩漏手牌或執著度數值。
- 新發的手牌和公牌有翻牌動畫。名次改變時，玩家標籤從舊位置滑到新位置。剛鎖定的玩家標籤彈跳 1 下。
- 攤牌從名次 1 開始逐列翻開手牌和對錯。全部翻完後，才顯示成功或失敗、比分和「下一局」。
- 系統設定「減少動態效果」時，關閉所有動畫，公告文字照常顯示。

**版面需求：**
- 以手機直向為主，寬度 360px 可完整操作。
- 名次列在 N = 13 時可橫向捲動，或改為 2 排。
- 不使用瀏覽器原生的 `alert`、`confirm`。

## 13. 假設（待使用者確認）

| # | 假設 | 理由 |
|---|---|---|
| A1 | 衝突與挑戰採「全員付費」：落敗者也扣除提交的執著度。 | 若只有勝者付費，玩家會傾向全押，預算失去意義。 |
| A2 | 交換請求的回應時限為 10 秒，拒絕後的挑戰決定時限為 5 秒。 | 避免單筆請求卡住整個交換階段。 |
| A3 | 同 1 組玩家在同一個交換階段只能有 1 筆請求。 | 防止重複騷擾。 |
| A4 | 挑戰中 A 的執著度必須「嚴格較高」才互換；相等時看提交先後。 | 與衝突處理的平手規則一致。 |
| A5 | 視窗超時未提交視為提交 0。 | 不提交就不消耗預算，也不會取得名次。 |
| A6 | 第 2–4 輪的選名次限時仍為 20 秒。 | 沿用原規則。 |
| A7 | 房主收到截止時間後 300 毫秒內的操作仍然接受。 | 吸收網路延遲，避免玩家按到但沒生效。 |

## 14. 時間估計

每局 = 4 ×（20 秒選名次 + 最多 10 秒執著度 + 60 秒交換）+ 攤牌 ≈ 6–7 分鐘。
1 場最少 3 局、最多 5 局，約 20–35 分鐘。
